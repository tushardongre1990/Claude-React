# Coding Interview Problem Bank

A dedicated bank of hands-on coding problems, separate from the chapter notes in
[`notes/`](../notes/). Chapter notes teach concepts; this bank is where those concepts get
tested under interview-style time pressure.

- [`react/`](react/README.md) — React implementation problems (build a debounced search, a
  virtualized list, a data table, etc.)
- [`javascript/`](javascript/README.md) — plain JavaScript problems, framework-free (debounce,
  LRU cache, event emitter, etc.) — these get asked independently of React at 5-10 YOE

## Format (once a problem is unlocked)

Each problem gets: **Requirements → Constraints → Starter code → Expected behavior → Hints →
Solution → Follow-up questions**. The follow-ups matter most — senior interviews rarely stop
at a working solution, they escalate ("now make it handle 100k rows", "now make it
accessible", "now make it cancellable").

Like the chapter notes, **problems are listed here as an index only** — a problem gets its
full write-up (starter code, solution, follow-ups) when you explicitly pick it to work on, not
before. See [`/CLAUDE.md`](../CLAUDE.md) for the full working rule.
