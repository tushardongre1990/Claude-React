**Status:** Not Started

## Why this chapter matters for a 5-10 YOE interview
A11y (Accessibility) and Core Web Vitals fluency signal production experience beyond 'it works on my machine'.

## Topics to cover

- Semantic HTML first, ARIA (Accessible Rich Internet Applications) as a last resort
- WCAG (Web Content Accessibility Guidelines) basics and accessible names
- Keyboard navigation, focus management, and focus restoration; avoiding keyboard traps
- Screen reader considerations for dynamic content (aria-live regions)
- Reduced motion, color contrast
- Accessible forms, loading states, and error states (`useId` for label/description wiring —
  introduced in ch.09, revisited here from the a11y angle)
- Core Web Vitals (LCP (Largest Contentful Paint), INP (Interaction to Next Paint), CLS (Cumulative Layout Shift)) and how React apps affect them
- Performance budgets and bundle analysis
- Audit tooling: Lighthouse, axe

## What you'll build
An accessibility + performance pass over an earlier chapter's project (including a genuinely accessible modal), with before/after audit scores.
