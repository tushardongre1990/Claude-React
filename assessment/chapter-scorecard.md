# Chapter Scorecard

Self-assessment for each completed chapter. Fill in a row after finishing a chapter's
exercises — be honest, this is diagnostic, not a grade. Anything scoring 3 or below should get
an entry in [`improvement-tracker/weak-areas.md`](../improvement-tracker/weak-areas.md) if it
doesn't already have one.

**Scoring guide (per skill, out of 5):**
- **5** — Could explain/do this cold, unprompted, in an interview right now
- **4** — Solid, would need a few seconds to organize the answer
- **3** — Understand it but answer would be shaky or incomplete
- **2** — Recognize it but couldn't reliably explain or apply it
- **1** — Would draw a blank

**Skills scored per chapter:**
- **Explain** — can you explain the concept clearly, out loud, to an interviewer?
- **Code** — can you write correct code using it without looking anything up?
- **Debug** — could you spot/fix a bug involving this concept in someone else's code?
- **Design** — can you reason about when/why to use it vs alternatives?
- **Interview** — have you actually rehearsed answering a question about this out loud?

**Readiness threshold:** average ≥ 4 across a chapter generally means it's interview-ready.
3-3.9 means a revision pass is worth doing before an interview. Below 3 means revisit the
chapter's exercises, not just its `revision.md`.

**Critical-topic floor — don't rely on the average alone.** A chapter (or the whole syllabus)
averaging well can still hide a dangerous gap: e.g. Security at 2.5 inside an otherwise-4.2
average is a real interview risk that the average hides. Treat **no chapter below 3** as a
harder constraint than "average ≥ 4 overall," and prioritize revisiting any single sub-3
chapter before polishing chapters that are already at 4+.
